# Student walkthroughs (how real students use Chaky)

Each row is a real situation, what Chaky should do, and the friction we found and fixed. Re-run these by hand before each release.

| # | Student | Says | Chaky does | Friction found → fix |
|---|---|---|---|---|
| 1 | Master's, vague topic, nothing yet | "guide me" | Suggests `update-repo`; a few setup questions one at a time → repo → seeded board with priorities → suggests `brain-dump` to pull out the idea and agree 3-5 terms | Too many setup questions → needs and terms first, repo details defaulted, mode asked once |
| 2 | PhD, data and notes, no repo | "guide me" | Adopt mode: mapping table, asks before moving; board seeded from what exists | Fear of being restructured → nothing moves without a yes; existing work marked 🟡/✅ |
| 3 | PhD who knows what they are doing | "let me lead" | Shows the board and waits; suggests only when asked | Chaky felt pushy → lead mode is quiet by design |
| 4 | Week 6: finds a very close paper | "I found a new paper" | Verified card, overlap level, 6 options, a ticket; main plan untouched until chosen | Panic → overlap is a level, not a verdict; "differentiate" is a ticket with a done-when |
| 5 | Pilot contradicts the hypothesis | tells Chaky | Logs the dead end, reopens the `decide` ticket, marks the paper ⚠ | Feels like failure → dead ends are a milestone and logged with the lesson |
| 6 | Non-native English speaker | sets language; "unslop this" | Explains in their language; paper stays English; voice notes from past papers; unslop pass | Output sounded generic → unslop pass and `voice.md` run on every section |
| 7 | Wants to submit tomorrow | "can I submit now?" | Submission mode: blockers first, then should-fix, then nice-to-have | Long checklist overwhelms → ordered by consequence, ~8 lines per report |
| 8 | Returns after two weeks | "guide me" | Leads with what needs attention, why, an example, one "Next:"; shows stale rows and top 3 tickets | Forgot context → board plus log plus status carry the memory |
| 9 | Advisor wants an overview | "progress update" | One page: tickets closed, results, dead ends, review trend, decisions needed | Advisors want brevity → fixed one-page format; lab rhythm from Lab defaults |
| 10 | Pastes participant data into a chat | (attempts commit) | Hook blocks; Chaky explains why and offers the safe path | Rule alone wasn't enough → pre-commit guard |
| 11 | Unsure what is "good enough" | "is this enough?" | Checks the ticket's done-when; closes it automatically if met (can be reopened), else split / park / accept | Endless polishing → every ticket has a done-when and a time box |
| 12 | Gets reviews back | pastes reviews, "/write response" | Groups the points; answers each as changed / clarified / disagree / out of scope with locations; fixes become tickets | Rebuttal felt overwhelming → one point at a time, most important first |
