# Idea lenses

Pick **2-3** that fit the situation; don't run all of them. Ask the user to answer each in a sentence or two. Ideas adapted in our own words; see the README credit.

| Lens | Ask |
|---|---|
| **Problem-first / solution-first** | Which are you in: a pain point looking for a method, or a method looking for a problem? Is the missing half real? |
| **Abstraction ladder** | Move **up** (what is this an instance of?), **down** (what is the smallest concrete case?), **sideways** (same level, adjacent domain). What do you see at each level? |
| **Borrow from another field** | Which field already solved the structure of this problem? What does the analogy predict that you can test? An analogy with no testable prediction is decoration. |
| **What changed?** | Take an old negative result or abandoned approach (3-10 years old). List why it was rejected. Which of those reasons (compute, scale, data, tooling, regulation, behavior) no longer hold? |
| **Resolve a tension** | Which two widely accepted goals pull against each other (e.g. privacy vs personalization)? What would satisfy both? |
| **Bisociation** | Combine two normally unrelated frames. What does each reveal about the other? |
| **Structure-mapping** | Map the relations (not surface features) of a well-understood system onto yours. Where does the map break? That break is often the finding. |
| **Constraint play** | Remove a constraint everyone accepts, or add a harsh one. What becomes possible or necessary? |

After a lens produces candidates, run the gap test in `SKILL.md`, then log the choice (and the rejected options) in `log.md`.
